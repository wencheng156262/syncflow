# SyncFlow 产品与技术范围

## 目标

SyncFlow 面向需要批量导入 CSV 数据的业务人员，提供可追踪的异步任务。用户不需要等待整个文件处理完成，就可以得到任务编号，并持续查看任务状态、统计和错误原因。

## 用户角色

| 角色 | 职责 |
| --- | --- |
| 数据操作人员 | 上传 CSV、创建任务、查询状态、查看结果和错误 |
| 系统维护人员 | 查看日志、定位失败任务、重试任务、维护本地环境 |

本项目第一阶段不实现登录和权限控制，所有页面和接口默认对本地访问者开放。

## 核心流程

1. 用户在 Web 页面选择 CSV，并可填写任务名称。
2. API 校验扩展名、大小和请求参数，将文件保存到受控目录。
3. API 在 MySQL 创建 `PENDING` 任务并把任务 ID 放入 Redis 队列，然后立即返回。
4. Worker 从 Redis 获取任务，将任务改为 `RUNNING`，执行处理并记录时间和结果。
5. Worker 将任务改为 `SUCCESS`、`PARTIAL_SUCCESS` 或 `FAILED`，并保存成功记录、错误记录和统计数据。
6. Web 通过 API 查询任务列表和详情，并展示加载、空数据、错误和最终结果。

## 第一阶段模块

| 编号 | 模块 | 第一阶段边界 |
| --- | --- | --- |
| F1 | 创建同步任务 | CSV 上传、文件校验、任务入库、投递队列 |
| F2 | 任务查询 | 列表、详情、状态筛选、分页 |
| F3 | CSV 校验与处理 | 文件级校验；逐行处理能力由后续周任务完善 |
| F4 | 异步 Worker | Redis 消费、状态更新、日志和优雅停止基础 |
| F5 | 任务状态机 | 状态定义和合法转换 |
| F6 | 重试机制 | 记录重试次数和错误原因，具体策略后续实现 |
| F7 | 幂等与去重 | 幂等键、文件摘要和业务唯一约束 |
| F8 | 任务取消 | 取消等待中或执行中的任务，后续实现 |
| F9 | Web 页面 | 任务列表、详情、创建入口和通用状态展示 |

## 非功能要求

- 所有服务可以在本地通过 Docker Compose 启动。
- 配置从环境变量读取，`.env` 不提交，`.env.example` 列出所有配置项。
- API 使用 `/api/v1` 前缀和统一 `{data, meta}` / `{error}` 响应。
- API 不返回内部文件路径、SQL、堆栈和连接信息。
- 文件名使用服务端生成的存储名，禁止目录穿越。
- 日志至少包含时间、级别、服务名和 `job_id`。
- 处理 1,000 行合法 CSV 时服务不应异常退出；10,000 行应采用流式或分批处理。
