# SyncFlow Web 页面设计

## 路由

| 路由 | 页面 | 目标 |
| --- | --- | --- |
| `/` | 任务列表页 | 查看任务、筛选状态、分页、进入详情 |
| `/jobs/new` | 创建任务页 | 选择 CSV、填写名称、提交任务 |
| `/jobs/:jobId` | 任务详情页 | 查看状态、统计、时间和错误摘要 |
| `*` | 404 页面 | 提供返回任务列表入口 |

## 任务列表页

首次加载调用 `GET /api/v1/jobs`。每行展示名称、状态、文件名、总数、成功数、失败数和创建时间。状态同时使用中文文本和颜色标识，不能只依赖颜色。

必须覆盖：加载中、空数据、请求失败、分页切换、状态筛选同步到 URL，以及进入详情页。

## 创建任务页

提供文件选择、文件名展示、任务名称和提交按钮。提交时使用 `multipart/form-data`，成功后跳转任务详情页或列表页并显示 `PENDING`。需要在前端提前提示非 CSV 文件和超过大小限制的文件。

## 任务详情页

首次加载调用 `GET /api/v1/jobs/{job_id}`。展示状态、源文件名、总记录、成功记录、失败记录、重试次数、创建/开始/结束时间和最近错误。任务不存在时展示明确的 404 页面，并提供返回列表入口。

## 通用交互规则

- 所有页面都处理加载、空数据和请求失败三种状态。
- 日期按浏览器本地时区展示，格式统一为 `YYYY-MM-DD HH:mm:ss`。
- 错误信息优先使用 API 的 `error.message`，不可展示堆栈。
- API 地址从 `VITE_API_BASE_URL` 读取，不写死在业务组件中。
